# 平台管理员初始化与运维操作手册

本文面向 ZTX 部署和运维人员，说明平台管理员首次初始化、日常登录、安全配置及故障处理。平台管理员属于控制面身份，与租户内的企业管理员账号相互独立。

## 1. 操作前检查

- 确认已按部署文档完成 PostgreSQL 配置、数据库迁移和 Server 启动。
- 确认 Server 健康检查正常：`http://127.0.0.1:8080/health/ready`。
- 确认部署人员具有服务器本机或 SSH 登录权限。
- 不要使用默认管理员账号、默认密码或一次性初始化口令；当前流程不生成这些凭据。

开发环境可在仓库根目录执行：

```bash
./ztx dev
```

正式环境按部署流程启动已迁移的应用。生产环境数据库迁移由受控部署流程执行，应用启动只校验迁移状态。

## 2. 首次初始化

### 2.1 在服务器本机初始化

在服务器本机浏览器打开：

```text
http://127.0.0.1:8080/platform/login
```

如果服务器没有图形桌面，使用 SSH 本地端口转发。

### 2.2 通过 SSH 隧道远程初始化

在部署人员自己的电脑上执行：

```bash
ssh -L 18080:127.0.0.1:8080 <部署用户>@<服务器地址>
```

保持 SSH 会话运行，然后在本机浏览器打开：

```text
http://127.0.0.1:18080/platform/login
```

不要将初始化入口直接暴露给公网。初始化 API 在服务端校验连接来源，只接受回环连接；不信任 `X-Forwarded-For` 等代理头。通过公网域名或普通反向代理访问初始化接口会被拒绝。

### 2.3 创建管理员

首次初始化页面只需填写：

1. 管理员用户名；
2. 密码；
3. 确认密码。

用户名为 3–80 位，仅允许英文字母、数字、点、下划线和连字符。密码至少 8 位，并且必须同时包含字母和数字。

提交成功后系统创建唯一的平台管理员并自动登录。初始化成功后，初始化 API 永久关闭；服务重启、重新部署或再次访问页面都不能重新开放初始化，也不能借此重置密码。

**安全要求：** 使用唯一且强度足够的密码，通过密码管理器保存。不要把密码写入部署脚本、命令行参数、日志、工单或代码仓库。

## 3. 日常登录与平台工作区

初始化完成后，平台管理员从以下入口登录：

```text
https://<ZTX访问域名>/platform/login
```

本地开发通常使用 `http://localhost:5173/platform/login`（Vite）或 `http://localhost:8080/platform/login`（Server 静态资源入口）。

使用初始化时设置的用户名和密码登录。平台管理员进入独立的平台管理工作区，不使用租户企业登录入口，也不会因此获得企业业务数据权限。

平台会话使用安全 Cookie 管理，默认有效期为 8 小时。退出登录会撤销当前会话。

## 4. 修改密码

已登录的平台管理员可在平台工作区的账户安全功能中修改密码，需要提供当前密码和新密码。新密码仍须至少 8 位，并同时包含字母和数字。修改成功后，其他已有平台会话会被撤销，当前会话保留。

## 5. MFA（可选）

MFA 初期不强制启用。未启用时，平台管理员可以仅使用用户名和密码登录。

如需启用 MFA：

1. 在服务器受保护的外部配置文件（例如部署使用的 `application.yaml`）中配置 `security.mfa-encryption-key`。
2. 使用以下命令生成随机密钥：

   ```bash
   openssl rand -base64 32
   ```

3. 将命令输出的完整字符串作为配置值保存：

   ```yaml
   security:
     mfa-encryption-key: "<生成的随机字符串>"
   ```

4. 妥善备份该密钥，并限制配置文件读取权限；不要提交到 Git 或写入日志。
5. 重启/重新部署 Server 使配置生效。
6. 平台管理员登录后，在账户安全页面发起 MFA 绑定，使用认证器应用扫描二维码或录入密钥，再输入动态验证码完成启用。

该配置值至少需要 32 字节。密钥用于加密保存 MFA 秘密；丢失或随意更换可能导致已保存的 MFA 秘密无法解密。MFA 启用后，登录时还需输入动态验证码。

## 6. 密码遗失与恢复边界

平台管理员密码遗失时，不能通过首次初始化页面重新创建，也不能通过公开 Web 找回入口恢复。

服务器受控命令重置能力由 [Issue #24](https://github.com/ljm20088/ztx/issues/24) 跟踪，当前版本尚未交付该命令。因此：

- 不要尝试再次调用初始化 API；
- 不要直接手工修改管理员密码哈希或数据库记录；
- 不要删除管理员记录来重新触发初始化；
- 在受控重置命令交付前，联系 ZTX 维护人员按经审核的恢复方案处理。

未来受控重置命令必须只重置现有唯一管理员、撤销其全部会话、保留已启用的 MFA，并记录成功或失败审计；不得创建第二个管理员或重新开放初始化。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 初始化页面提示必须本机访问 | 使用服务器本机浏览器，或按第 2.2 节建立 SSH 本地端口转发。 |
| 通过公网域名初始化返回拒绝 | 这是预期安全行为。不要通过修改代理头绕过限制，改用 SSH 隧道。 |
| 页面显示已初始化 | 管理员记录已存在，首次初始化不能再次使用；使用日常登录流程。 |
| 密码不符合要求 | 至少 8 位，并同时包含字母和数字。 |
| 登录时要求动态验证码 | 该管理员已启用 MFA；使用绑定的认证器应用生成验证码。 |
| MFA 绑定时报密钥配置错误 | 检查外部 `application.yaml` 的 `security.mfa-encryption-key` 是否至少 32 字节，并确认 Server 已加载新配置。 |
| 平台登录或状态接口返回服务不可用 | 检查 Server 日志、PostgreSQL 连通性和 `/health/ready`；不要将密码、Cookie 或 MFA 密钥贴入工单。 |

## 8. 安全检查清单

- [ ] 初始化通过服务器本机或 SSH 本地端口转发完成。
- [ ] 公网入口未开放初始化 API。
- [ ] 管理员使用独立强密码，未复用其他系统凭据。
- [ ] 数据库备份和外部配置文件已纳入受控备份。
- [ ] MFA 如已启用，其加密密钥已安全备份并限制读取权限。
- [ ] 不在日志、命令参数、Shell 历史或代码仓库中保存密码、会话 Cookie 或密钥。
- [ ] 定期检查平台安全审计记录。
